## 1. What the evidence establishes

The unchanged path is native tick -> inspection dispatch -> dynamic owner tick -> retained-file custody, followed at outer reader boundaries by root/epoch/root sampling. Sampling invokes native reads and more guarded checks. The existing epoch_sampling flag already bounds recursive epoch sampling; do not call this infinite recursion.

Historical diagnostic counters supported CPU-active guard amplification. The uninstrumented CONF-FIX-009 attempt failed at the same factory and supplied watchdog stacks, not exclusive function timings. Its tuple inlining left the multiplicative structure unchanged. Neither dataset establishes that a particular optimization will fit750 seconds, or that Linux production has the same timing.

A new allowance is not a reason to repeat the same candidate. The successor needs a materially justified design before code or product execution.

## 2. Runtime design gate

Potential edit ownership is limited to these seven existing methods/functions in live_proxy_server.py:

1. _Files.check
2. _KernelNativeReads._tick
3. _kernel_inspection_tick
4. _KernelSelfInspection._tick
5. _KernelSelfInspection._reader_tick
6. _KernelRootViews._reader_mounts
7. _KernelPolicyView._reader_epoch

New private helper names must be explicitly listed, justified and independently reviewed before writing them. Other runtime regions stay byte-identical. In particular, retain dynamic observer/broker override behavior; qualification and admission are not a self-inspector-only problem.

The design record must identify, for each proposed change:

| Obligation | Required evidence before implementation |
|---|---|
| Exact old/new path | Ordered native and Python-observable operations; named removed/relocated work |
| Mutable observations | Fresh stat/path/FD/inheritability, root/mount/namespace, epoch and peer observations at their existing boundaries |
| Temporal safety | Change after one leaf operation and restoration at the next; refusal still precedes the next consequential operation |
| Dynamic ownership | Original self/observer/broker dispatch, retained resource identity, thread/process ownership and reader membership |
| Error ordering | Short-circuit order, attribute/iterator/OS errors and rich-comparison truthiness retain semantics |
| Lifetime | Original monotonic/wall/authority windows, expiry and sticky failure; no renewed deadline |
| Cleanup | Partial acquisitions close original resources; recycled descriptors are not accidentally closed |
| Cost argument | Which repeated work disappears or gets cheaper and why, without an unmeasured speedup assertion |

Already identified counterexamples remain binding:

- Phase-entry/exit-only sampling can miss a mutation between fstat and fcntl that the intervening tick currently detects.
- Skipping custody inside epoch_sampling can miss an authority-file/FD mutation restored before an enclosing check.
- Root-before and root-after observations protect different boundaries; neither is redundant merely because the other passed.
- Cached earlier observations do not prove mutable state unchanged.
- A self-only guard bypasses stronger observer/broker checks.
- A naive generator-to-loop rewrite changes StopIteration exception behavior.

No blanket cache, scan elision or reduced polling frequency is approved. Trace-preserving computation changes may be considered, but no benefit is promised. Any observation removal or relocation needs an independently accepted equivalence argument covering these interleavings. A design requiring a new temporal contract or independently enforced mutation exclusion is outside this repair packet: STOP_NOT_WAIVE and prepare a separate architecture amendment. Enforcement must exist before qualification and cannot be asserted based on the qualification it is intended to secure.
