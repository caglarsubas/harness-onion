W01 has advanced from an ownership table to a concrete, reviewable design. It is
**not closed**: the new API-proxy enforcement interface, complete policy-writer
mediation and exact host privilege/lifecycle policies still need review and a
versioned amendment. W02-W07 and CONF-FIX-009/010 remain unavailable for dispatch.

The architectural recommendation is to reuse the existing signed
KUBERNETES_API_PROXY endpoint as the operation boundary, never add a campaign
endpoint or put credentials in a worker. A proposed native gate there owns the
operation lifecycle; a separate private broker channel would arm one exact action.
Do not select Kubernetes admission, an authorization webhook, a watcher or an
Envoy callback as a complete substitute for this lifecycle without proof.

If the external API-proxy/control-plane backend cannot mediate every relevant
writer, the resource-bearing live qualification capability remains unavailable.
The product's general Kubernetes portability promise must not be narrowed by
silently imposing control-plane ownership on every enterprise tenant. Zero-resource
mode is not an escape: existing observer and broker prerequisites still apply.
