## Rules

- scope: A licence text without a stated scope governs its own directory only; a subdirectory that carries its own licence text is a separate part (the nearest licence text). A text whose wording states a scope (a root LICENSE that names directories under another licence, or the text it designates for them) governs every directory under the stated prefixes except the excluded ones, nested licence texts included, so such a part holds both identifiers. A same-blob copy of a scope-stating text in a subdirectory governs that directory only: the directories its words name are the repository's, not the copy's.
- aggregation: A part's licence set is the SPDX identifiers of the texts governing it. A part, a repository (all its parts) and a scoped artifact take the highest-precedence outcome present under policy 0.3.0 (DENIED, then UNKNOWN as DENY_UNKNOWN_LICENSE, PLANNED_UNRESOLVED, OPTIONAL_EXPLICIT_REVIEW, OPEN_CONTENT, ALLOWED_EXCEPTION_EXPRESSION, DEFAULT_ALLOWED), and every member's obligations apply.
- ceiling: REUSE_AFTER_GATES for DEFAULT_ALLOWED and ALLOWED_EXCEPTION_EXPRESSION, DESIGN_REFERENCE_ONLY otherwise (the v2 crosswalk's rule).
- scopedArtifact: A proper subset of a repository's parts named for planning, such as the tree without an enterprise directory or one subpackage; an adoption re-establishes the licence set on the artifact it actually takes. Its licence set covers only the licence texts in its directories at the pinned commit: dependency closure, vendored or third-party code without its own licence text, and any reach into an excluded directory stay open.
